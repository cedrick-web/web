# DevSprint Assessment Simulator

## Purpose

Simulate a coding assessment without immediately reaching for the reference answer.

## Rules

- Choose a quiet session.
- Set a 60-minute timer.
- No reference solutions during the first attempt.
- Write input/output notes before code.
- Write pseudocode before implementation.
- Test edge cases.
- Record time and space complexity.
- After the timer, review your work using the rubric.

## Part A: Fundamentals

1. Write `countPositive(numbers)`.
2. Write `findSmallest(numbers)` for a non-empty array.
3. Write `containsIgnoreCase(words, target)`.
4. Write `lastIndexOfValue(numbers, target)` without the built-in method.

## Part B: Algorithm choice

5. Explain when a linear search is preferable to binary search.
6. Explain why a `Set` can improve duplicate detection.
7. Compare an O(n) approach with an O(n²) approach for a duplicate-detection problem.

## Part C: Integrated problem

Build a small student-report function that:

- calculates each student's average;
- determines pass/fail using average >= 50 and attendance >= 75;
- ranks students by average;
- reports attendance risks;
- returns summary statistics.

Use the Final Project as the larger version after the assessment.

## Scoring rubric

| Skill | Points |
|---|---:|
| Problem interpretation | 10 |
| Algorithm design | 20 |
| JavaScript implementation | 20 |
| Edge cases and tests | 15 |
| Debugging | 10 |
| Complexity analysis | 15 |
| Explanation and clarity | 10 |
| **Total** | **100** |

## Results

- 90–100: strong readiness for independent project work
- 75–89: solid, but review weak areas
- 60–74: repeat targeted modules and retry
- Below 60: return to Modules 1–3 and rebuild the problem-solving process

Record the score and the three weakest skills. Improvement is more useful than a pretty number.
